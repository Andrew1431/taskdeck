# Changelog

## Unreleased

### Contract (see CONTRACT.md)
- **`each:` templates.** Write an action once and repeat it over a list:
  `up-{service}: { title: "Start {service}", group: "{service}", run: mycli up {service}, each: { service: [web, api, worker] } }`
  makes `up-web`, `up-api` and `up-worker`. With several keys you get one copy per
  combination. `{name}` is replaced in the id and in every string inside the entry, and the id
  must use every key. `each` also works on `links` and `groups`. The list is static: re-render
  the contract when it changes. A dynamic list from a command, like `choicesFrom`, isn't
  supported yet.
- **`links:`** become open-in-browser buttons. Each link takes `title`, `url` (http/https) and
  optionally `group` and `description`. A link with a group shows in that group's header;
  one without shows at the top of the repo page. `taskdeck list` and MCP `taskdeck_list` list
  them too, so agents know the URLs. Opening a link isn't a run, so it doesn't show up in run
  history.
- **`groups:` with `health:`** gives a group a live up/down dot in the UI, for services another
  CLI starts and owns. `health` is a URL (up when it answers with a status below 500) or
  `{ run: command, cwd? }` (up when it exits 0). The UI checks every 5s; results are cached
  for 3s. MCP `taskdeck_list` adds a "Status:" section with each group's state, so agents can
  ask taskdeck instead of probing ports. A `status` command whose JSON output is mapped onto
  groups isn't supported: use one `run:` per group, templated with `each`.
- **`generatedBy: { tool, regenerate }`** marks a contract a tool writes. The UI shows a
  banner ("Generated by mycli. Edits to this file are overwritten; change the source and run
  `mycli render`"). `taskdeck list`, `taskdeck check` and MCP `taskdeck_list` say the same,
  telling agents not to edit the file by hand. `check` still reports drift.
- YAML note: quote strings that start with `{` or contain `{name}` inside a `{ flow: map }`,
  e.g. `title: "Open {service}"`.

### MCP
- `taskdeck_run_status` takes `wait_seconds` and waits for a running run to finish, the same
  way `taskdeck_run` does, so agents don't need sleep loops. The default (0) returns right away,
  as before. To wait on several runs, call it for each run in parallel.
- `taskdeck_run_status` and `taskdeck_recent_runs` show elapsed time for running entries
  ("running for 18s").
- `taskdeck_add` says "Already added: …" when the folder is already registered.

### CLI
- `taskdeck --version` (or `taskdeck version`) prints the version and exits.
- `taskdeck add` on a folder that's already registered prints "Already added: <name> (id …)"
  and still exits 0. `--json` prints the repo summary with `added: true|false`.
- `taskdeck show` describes a param's `default` as "if omitted, the command uses 80". The
  `default` is documentation; taskdeck never passes it.
- On startup time: taskdeck starts in about 0.1–0.3s. Most of the time `npx taskdeck` takes is
  npx's own overhead. Tools that call taskdeck often should install it globally
  (`npm i -g taskdeck`) and call `taskdeck` directly.

### UI
- A param's `default` shows as "If omitted, the command uses …", matching `show`.
